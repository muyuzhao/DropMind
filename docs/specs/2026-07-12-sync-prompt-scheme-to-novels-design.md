# 提示词方案同步到已有小说设计

## 目标

解决“修改提示词方案后，已有小说仍使用创建时旧快照”的问题。用户可以从提示词管理页手动选择一套方案，将其完整六步提示词同步到一个或多个已有小说。

## 入口与交互

每个提示词方案的管理区域增加“同步到已有小说”按钮。

点击后展开同步区域：

1. 显示全部已有小说及复选框；
2. 用户可选择一个或多个小说；
3. 页面明确提示：“将使用【方案名】覆盖所选小说的全部 6 个提示词”；
4. 未选择小说时禁用确认按钮；
5. 点击确认后再调用同步操作；
6. 同步完成后显示成功同步的小说数量。

第一版不增加搜索、分页、方案永久绑定或自动同步。

## 同步规则

- 方案必须存在且正好拥有六个有效步骤模板；
- 所选小说必须存在；
- 在单个数据库事务中，将方案的六个模板复制到每个小说的 `prompt_templates` 快照；
- 只更新模板正文和更新时间，不改变快照记录标识；
- 同步全部成功或全部回滚，不允许部分小说处于新方案、部分处于旧方案；
- 重复同步是安全的，结果与方案当前内容一致。

## 数据边界

同步只修改 `prompt_templates`。以下内容一律不变：

- 小说名称、参考书名和简介；
- 最终选题、本卷大纲和核心设定；
- 剧情单元、分章大纲和章节正文；
- 章节状态、版本记录和当前步骤；
- 提示词方案本身。

小说不会与方案建立永久关联。方案以后再次修改时，用户需要再次手动同步，防止无意覆盖小说快照。

## 接口与错误处理

仓储层提供 `syncPromptSchemeToNovels(schemeId, novelIds)`，返回同步的小说数量。

服务端操作负责：

- 验证 `schemeId` 非空；
- 去重并验证 `novelIds` 至少包含一个值；
- 调用仓储事务；
- 成功后刷新 `/novels/prompts` 和被同步小说页面；
- 将“方案不存在”“方案不完整”“小说不存在”等错误显示在同步区域。

## 验证

- 仓储测试验证六个模板全部覆盖；
- 测试验证小说创作内容保持不变；
- 测试验证方案不完整或小说不存在时整体回滚；
- 测试验证重复小说 ID 只计数一次；
- 组件交互至少通过类型检查和生产构建；
- 完整运行 Vitest、TypeScript、ESLint 和 Next.js 生产构建。
