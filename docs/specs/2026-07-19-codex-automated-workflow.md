# Codex 本地自动生成流水线

## 边界

自动模式只覆盖第 2–5 步；第一步最终选题仍由用户确认，第六步正文继续走原有逐章手动/Codex 协作。DropMind 不调用模型 API，不保存 API Key，也不把 SQLite 交给 Codex。

Next.js Server Action 只创建任务、更新控制文件、轮询状态、校验输出和导入数据库。长期 Codex 进程由用户启动的独立 PowerShell 脚本托管，因此浏览器关闭或开发服务器页面刷新不会终止生成。

## CLI 调用

每个节点使用一次独立调用：

```text
codex exec -C <run-dir> --sandbox read-only --skip-git-repo-check --output-last-message <temporary-output> -
```

- 节点提示词从标准输入传入。
- `-C` 把读取范围固定到任务目录。
- 模型沙箱为 `read-only`；最终回复文件由 CLI 自身写入临时路径。
- 脚本记录标准输出、标准错误和退出状态，成功后才原子替换正式输出。
- 默认失败最多尝试两次，即自动重试一次。
- 可通过 `CODEX_CLI_PATH` 指定 CLI 完整路径。

当前 Codex 桌面应用内的受控开发进程无法执行 WindowsApps 下的 `codex.exe`（系统返回 Access denied），所以本机真实模型调用不能在该进程中完成。运行器参数和退出状态行为通过同接口的临时 CLI 夹具完成了端到端验证；用户从普通 PowerShell/CMD 启动生成脚本时会使用已登录的本地 Codex CLI。

## 任务与状态

任务目录位于 `data/novel-projects/<小说目录>/自动生成/<run-id>`。`manifest.json` 固化小说标识、输入摘要和 SHA-256、当前节点、总体状态、14 个节点的状态/尝试次数/输入输出日志路径/导入标记/失败原因。`control.json` 只承载运行、节点后暂停、终止和单节点重试请求。

节点状态为 `pending`、`running`、`completed`、`failed`、`paused`、`stale`。总体状态另包含 `terminated`。JSON、正式输出、日志和连续性文件都先写同目录临时文件，再原子替换目标文件。终止不会删除已经完成的输出。

14 个节点严格按以下顺序执行：分卷大纲、核心设定、六个剧情单元批次、六个分章大纲批次。第一版没有队列、并发或模型选择。

## 连续性与变化检测

`inputs/context.json` 固化最终选题、参考书名/简介、四个步骤的模板以及创建任务时已确认的正式内容。下游节点同时读取上游输出和 `outputs/continuity.md`。

每次 Codex 回复由导入正文和 `<!-- DROPMIND_CONTINUITY -->` 后的连续性摘要组成。运行器将两部分拆开，并累计人物位置/关系、目标、秘密、伏笔、时间线、冲突和禁忌矛盾。后续批次会读取累计摘要。

工作区轮询时比较正式内容与任务快照。选题、模板、分卷大纲、核心设定或剧情单元变化会把受影响的已完成节点及后续节点标记为 `stale`；这些节点不会自动导入。用户从指定节点重新生成时，该节点重置为 `pending`，后续节点标记为 `stale`。

## 导入事务与幂等

只有 `completed` 且未导入的节点才进入导入流程：

1. 文件必须存在且非空。
2. 分卷大纲必须包含五卷；剧情单元必须声明正确十章范围；分章大纲必须包含十个 `## 第N章` 标题。
3. repository 在 SQLite 事务内写入正式表。
4. 被替换的正式内容通过 `content_versions` 留档。
5. 分卷结果同时更新 `novel_steps.volumes` 和当前第一卷大纲字段。
6. 数据库提交后记录输出 hash 和导入标记。

如果数据库提交后、manifest 更新前进程中断，下一次轮询会重复同一次 upsert。repository 只在旧内容与新内容不同时创建历史版本，因此不会制造重复版本或重复行。

## 第一版限制

- 不自动启动后台进程；用户需要双击 CMD 或运行界面给出的 PowerShell 命令。
- 暂停和终止在当前节点结束后生效，不能中断正在进行的 Codex 调用。
- 不生成正文，不统计 token/成本，不提供多模型选择，不并行执行节点。
- 自动输出采用 Markdown 结构校验；语义质量和小说创作判断仍需用户复核，可随时返回手动模式修改。
