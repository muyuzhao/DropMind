# 连续创作工作流设计

## 目标

将已有六步功能串成一条可观察、可连续推进的第一卷生产线。用户可以自由浏览任意步骤，但系统必须明确显示前置条件、当前进度和下一项工作。

## 工作流

固定顺序为：

1. 保存候选选题结果并确认最终选题。
2. 保存完整分卷大纲并确认当前卷大纲。
3. 保存核心设定。
4. 依次完成六个十章剧情单元。
5. 依次完成六个十章分章大纲。
6. 依次完成 60 章正文。

“保存并进入”在批次或章节末尾继续进入下一项；第 51—60 章剧情单元完成后进入分章大纲，第 51—60 章分章大纲完成后进入第 1 章正文。

## 步骤状态

每个步骤显示四种状态：

- `blocked`：缺少前置内容；
- `ready`：可以开始；
- `in_progress`：已有部分正式内容；
- `complete`：当前步骤的全部正式内容已完成。

阻塞状态只提供引导，不禁止用户打开页面。提示词缺失项应可点击并跳转到对应步骤。

## 批次与章节导航

- 剧情单元和分章大纲按六个十章范围展示；
- 正文按六个十章组展示每组完成数量；
- 章节状态包括缺少前置内容、可写、已保存和已发布；
- 正文提供上一章、下一章和首个可写章节快捷操作；
- 发布状态只修改章节状态，不产生重复正文历史版本。

## Codex 正文状态

Codex 面板显示以下阶段：

```text
未同步 → 资料已同步 → 任务已准备 → 检测到正文 → 已导入
```

系统根据项目目录、当前任务文件、正文文件和数据库正文动态判断阶段。准备任务时同步资料并复制短指令；导入前沿用内容差异确认和并发修改检查。

## 数据边界

SQLite 仍是已确认内容的主数据源，Codex Markdown 是写作工作副本。本设计不改变数据库结构、备份格式或小说目录结构。
