# Codex 连续正文生成设计

## 目标与范围

第六步增加独立的本地正文流水线。用户选择起始章节和连续生成数量，单次生成 1–10 章，范围限制在第一卷第 1–60 章。每章使用一次独立 `codex exec`，严格串行，支持章节后暂停、继续、失败章节重试、终止、输出与日志预览。

## 资料读取

章节节点不重复嵌入完整大纲和设定，只提供任务与相对文件路径。创建任务前 DropMind 同步本地写作目录；Codex 按需读取：

- `资料/正文创作要求.md`；
- 当前十章的剧情单元和分章大纲；
- 分卷大纲、本卷大纲、核心设定等其他本地资料；
- 第一节点之前的工作台已确认正文，或本次任务上一节点的输出；
- 创建任务时固化的 `inputs/continuity-base.md`；
- 当前任务不断替换的最新状态 `outputs/continuity.md`；
- 需要核对历史时按需读取已确认正文，连续性摘要只作为检索索引，不覆盖正文事实。

如果起始章大于 1，本地上一章正文必须与 SQLite 已确认正文一致，避免流水线建立在尚未导入的工作副本上。

## 数据安全

- 创建任务时记录规划资料摘要、上一章正文摘要以及目标章节的内容和更新时间。
- 同时记录连续性基线的截至章节、来源、revision 和内容 hash；基线变化时整批标记为 `stale`。
- 资料或上一章正文变化时，整批未导入结果标记为 `stale`。
- 目标章节在任务创建后被修改时，整批拒绝导入。
- 已发布章节不能加入自动生成范围。
- 每章输出正文、章节连续性事件和一份有界的最新状态快照。事件追加保存，当前状态替换保存，避免长篇上下文无限增长。
- 全部节点完成后才通过一个 SQLite 事务批量导入正文、连续性事件和小说级最新状态；已有正文覆盖前进入 `content_versions`。
- 人工修改旧章节正文时，该章及之后的连续性事件失效，小说级状态自动回退到之前最后一个有效快照。
- 已有小说若没有小说级状态，优先承接截至上一章的旧版已导入任务记录；仍找不到时，首个新版节点读取既有正文重建一次基线。
- 数据库提交后再写本地正文文件；文件同步失败不回滚已经安全提交的数据库正文，并向用户显示警告。

## 目录

```text
data/novel-projects/<小说目录>/自动正文/<run-id>/
├─ manifest.json
├─ control.json
├─ inputs/
│  └─ continuity-base.md
├─ outputs/
│  ├─ continuity.md
│  ├─ continuity-events/
│  └─ continuity-states/
├─ logs/
├─ run-pipeline.ps1
└─ run-pipeline.cmd
```
