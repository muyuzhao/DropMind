# DropMind

DropMind 是一个本地小说创作工作台，提供固定的七步创作流程：选题、分卷大纲、核心设定、剧情单元、分章节大纲、发布准备和章节正文。发布准备包含作品标签与番茄小说封面提示词。

它不调用 AI API。除生成提示词、保存模型返回内容、JSON 备份和正文 TXT 导出外，还可以通过本地 Chrome 扩展把已保存章节填入番茄作家后台。

## 连续创作流程

工作区将七步串成一条连续生产线：

```text
选题 → 分卷大纲 → 核心设定
→ 剧情单元 1-10 … 51-60
→ 分章大纲 1-10 … 51-60
→ 发布准备（作品标签、封面提示词）
→ 正文 1 … 60
```

- 选题需要同时保存模型生成结果并确认最终选题。
- 分卷大纲需要同时保存完整结果并确认当前卷大纲。
- 侧栏区分“缺少前置内容、可以开始、进行中、已完成”，仍允许自由查看任意步骤。
- 正文按六个十章组导航，可跳到上一章、下一章或首个可写章节。
- 正文可以标记为“已发布”，小说列表会统计发布数量。

## 启动

要求安装 Node.js 24 或更高版本。

最简单的方式是双击：

```text
start-novel-workbench.cmd
```

也可以在 PowerShell 中运行：

```powershell
npm.cmd install
npm.cmd run dev
```

然后打开 `http://127.0.0.1:3000`。开发和正式启动命令都只监听本机地址，不会主动向局域网开放。

## 数据与备份

本机结构化数据保存在 `data/novels.db`，Codex 写作目录保存在 `data/novel-projects`，整个 `data` 目录都不会提交到 Git。

- 在小说工作区使用“备份 JSON”保存完整工作台内容。
- 正式内容再次保存时会保留上一版；工作区可展开“历史版本”预览并恢复，恢复前的当前内容同样会留档。
- 在小说列表使用“导入备份”恢复为一本新的小说，不会覆盖原项目。
- 正文可以使用“导出正文 TXT”按章节顺序导出。
- 章节标题与正文分开保存；正式写作文件使用 `第001章__章节标题.md`，旧的 `第001章.md` 仍可读取。
- 数据库是已确认内容的主数据源；Codex Markdown 是写作工作副本。回读不同内容时，工作台会要求确认，并检测其他窗口是否已经修改正文。
- 破坏性数据库迁移执行前，会在 `data/backups` 创建 SQLite 快照。
- JSON 备份包含内容历史；旧版 version 1 备份没有历史字段时仍可正常导入。
- 番茄作品绑定和投递队列属于本机操作状态，暂不进入小说 JSON 备份；章节标题和正文仍由原有备份完整保存。

## 数据架构

- `src/lib/novel-db/initialize.ts` 中的 SQL 是 SQLite 表结构和迁移的唯一来源。
- `src/modules/novels/repository.ts` 负责事务、版本留档和 DTO 组装；页面只接收 `src/modules/novels/types.ts` 中的明确数据类型。
- 工作区容器负责编辑状态，侧栏、Codex 状态面板和历史面板分别作为独立展示组件维护。

## Codex 正文流程

正文面板按“未同步 → 资料已同步 → 任务已准备 → 检测到正文 → 已导入”显示当前状态。先准备当前章任务并复制指令，再以界面显示的小说目录作为 Codex 工作目录执行。Codex 写完后回到工作台预览并导入；如工作台版本和文件版本不同，确认后才会覆盖。

单章任务与批量正文节点使用同一套结构化输出协议：标题标记、纯正文、本章连续性事件、小说级最新状态快照。准备任务时会把恰好截至上一章的有效状态固化为 `当前任务连续性.md`，避免重写旧章时误读更后面的剧情；Codex 将完整结果保存为 `待导入/第001章.md`。工作台预览确认后，在一个事务中导入标题、正文、事件和状态，再把纯正文同步为 `正文/第001章__章节标题.md`。旧版直接写入 `正文/` 的单章文件仍可读取，但不会凭空生成连续性事件。

普通单章和批量正文任务都只能从第一处未写章节开始连续追加，不能覆盖已有正文或已发布章节。历史章节仍可打开和手工编辑；手工修改会按连续性规则使后续状态失效。自动批量任务处于运行或待导入状态时，不能再准备或导入单章任务。

数据库保存和 Codex 文件同步分别报告结果。若看到“内容已保存，但 Codex 目录同步失败”，内容已经安全写入数据库，可以在正文面板重新同步。

小说重命名时，本地 Codex 写作目录会同步改为新的小说名称，并保留小说 ID 后缀以及目录内的正文、资料和自动生成任务。若自动生成任务仍在运行或目标目录冲突，工作台会保留原目录并提示稍后重试，不会覆盖已有文件。

## 番茄单章投递

第一版采用“扩展填入、作者确认提交”的方式，不保存番茄账号、密码或 Cookie，也不会自动点击平台最终发布按钮。

1. 在第6步“发布准备”绑定番茄作品名和作品管理页。
2. 按页面说明，从 `browser-extension/fanqie-delivery` 加载本地 Chrome 扩展，并填写连接令牌。
3. 在第7步保存章节标题和正文，点击“投递到番茄”；可以连续将多章加入队列。
4. “自动投递第N章”始终处理同一本书队列中章节号最小的活动任务，不能跳过前章；“打开后台手动投递”只打开番茄后台，不自动领取或填入。
5. 核对平台页面后亲自提交，再在扩展面板点击“我已提交审核”。

投递任务会保存标题和正文快照。任务领取前如果工作台正文发生变化，旧任务会标记为“正文已变化”，不会静默投递旧版本。自动识别平台编辑器失败时，扩展仍提供复制标题和复制正文作为回退。

## Codex 自动生成第 2–5 步

第一步保存并确认最终选题后，工作区会出现“自动生成第 2–5 步”。手动模式仍然是默认模式，自动任务不会替换原有编辑、保存和历史恢复入口。

1. 点击“创建自动生成任务”。
2. 双击界面所示任务目录中的 `run-pipeline.cmd`，或复制 PowerShell 命令运行。
3. 脚本在浏览器之外串行执行 14 次独立 `codex exec`。可以关闭浏览器，脚本会继续运行。
4. 重新打开工作区后，自动面板每 3 秒读取一次 `manifest.json`；完成输出经范围和结构校验后，使用 repository 事务化、幂等地导入 SQLite。
5. 可请求“节点后暂停”、继续、单独重试失败节点、终止，或从指定节点重新生成。上游正式内容变化时，旧结果会标记为 `stale`，不会静默导入。

如果第 2–5 步已经手动完成一部分，新建或尚未启动的自动任务会沿用从“分卷大纲”开始连续完成的正式节点，把这些内容写入任务输出供下游读取，并从第一个缺失节点继续生成。遇到中间缺口后，缺口之后的旧内容不会被静默跳过。

任务保存在：

```text
data/novel-projects/<小说目录>/自动生成/<run-id>/
├─ manifest.json
├─ control.json
├─ inputs/
├─ outputs/
├─ logs/
├─ run-pipeline.ps1
└─ run-pipeline.cmd
```

运行器通过标准输入把单节点任务交给 Codex，并使用以下非交互调用形式：

```text
codex exec -C <run-dir> --sandbox read-only --skip-git-repo-check --output-last-message <temp-output> -
```

Codex 只读任务资料，不直接操作数据库；脚本检查退出状态、保留日志，并将完整输出原子重命名后再供 DropMind 读取。如 `codex` 不在 `PATH`，可以先设置 `CODEX_CLI_PATH` 为 `codex.exe` 的完整路径。

## Codex 连续自动生成正文

进入第 6 步后可以选择“自动生成正文”并指定连续生成数量，单次范围为 1–10 章且不超过第 60 章。系统自动从下一可写章节开始，按章节串行调用 Codex，后一章会读取前一章输出；全部章节完成、资料快照未变化且数据库正文没有并发修改后，才会事务化批量导入。

起始章节由工作台自动确定为第一处未写正文，不能手动选择更早或更后的章节。若历史中存在空档，必须先补齐最早空档；普通自动任务不提供覆盖已有正文的入口。

每个章节节点只接收本章任务和本地资料路径，不重复嵌入整套大纲与设定。Codex 按需读取小说目录中的 `资料/`、已有 `正文/`、当前任务的前章输出和 `outputs/continuity.md`。小说级已确认连续性保存在 SQLite 并同步到 `资料/连续性/当前状态.md`；创建新任务时会固化到 `inputs/continuity-base.md`。运行中逐章保存连续性事件和状态快照，当前状态采用替换而非无限追加，整批正文成功导入时才随正文事务一同晋升。任务支持本章后暂停、继续、失败章节单独重试、终止、日志与正文预览，任务文件保存在：

连续正文节点先输出结构化章节标题标记，导入时工作台会移除标记、分别保存标题与纯正文，并同步为带标题的正式正文文件名。

```text
data/novel-projects/<小说目录>/自动正文/<run-id>/
├─ inputs/continuity-base.md
├─ outputs/continuity.md
├─ outputs/continuity-events/
├─ outputs/continuity-states/
```
