# DropMind

DropMind 是一个本地小说创作工作台，提供固定的六步创作流程：选题、分卷大纲、核心设定、剧情单元、分章节大纲和章节正文。

它不调用 AI API，只负责生成提示词、保存从 Gemini 等模型粘贴回来的内容，并提供 JSON 备份和正文 TXT 导出。

## 连续创作流程

工作区将六步串成一条连续生产线：

```text
选题 → 分卷大纲 → 核心设定
→ 剧情单元 1-10 … 51-60
→ 分章大纲 1-10 … 51-60
→ 正文 1 … 60
```

- 选题需要同时保存模型生成结果并确认最终选题。
- 分卷大纲需要同时保存完整结果并确认当前卷大纲。
- 侧栏区分“缺少前置内容、可以开始、进行中、已完成”，仍允许自由查看任意步骤。
- 正文按六个十章组导航，可跳到上一章、下一章或首个可写章节。
- 正文可以标记为“已发布”，小说列表会统计发布数量。

## 启动

要求安装 Node.js 24 或更高版本。

最简单的方式是双击：

```text
start-novel-workbench.cmd
```

也可以在 PowerShell 中运行：

```powershell
npm.cmd install
npm.cmd run dev
```

然后打开 `http://127.0.0.1:3000`。开发和正式启动命令都只监听本机地址，不会主动向局域网开放。

## 数据与备份

本机结构化数据保存在 `data/novels.db`，Codex 写作目录保存在 `data/novel-projects`，整个 `data` 目录都不会提交到 Git。

- 在小说工作区使用“备份 JSON”保存完整工作台内容。
- 正式内容再次保存时会保留上一版；工作区可展开“历史版本”预览并恢复，恢复前的当前内容同样会留档。
- 在小说列表使用“导入备份”恢复为一本新的小说，不会覆盖原项目。
- 正文可以使用“导出正文 TXT”按章节顺序导出。
- 数据库是已确认内容的主数据源；Codex Markdown 是写作工作副本。回读不同内容时，工作台会要求确认，并检测其他窗口是否已经修改正文。
- 破坏性数据库迁移执行前，会在 `data/backups` 创建 SQLite 快照。
- JSON 备份包含内容历史；旧版 version 1 备份没有历史字段时仍可正常导入。

## 数据架构

- `src/lib/novel-db/initialize.ts` 中的 SQL 是 SQLite 表结构和迁移的唯一来源。
- `src/modules/novels/repository.ts` 负责事务、版本留档和 DTO 组装；页面只接收 `src/modules/novels/types.ts` 中的明确数据类型。
- 工作区容器负责编辑状态，侧栏、Codex 状态面板和历史面板分别作为独立展示组件维护。

## Codex 正文流程

正文面板按“未同步 → 资料已同步 → 任务已准备 → 检测到正文 → 已导入”显示当前状态。先准备当前章任务并复制指令，再以界面显示的小说目录作为 Codex 工作目录执行。Codex 写完后回到工作台预览并导入；如工作台版本和文件版本不同，确认后才会覆盖。

数据库保存和 Codex 文件同步分别报告结果。若看到“内容已保存，但 Codex 目录同步失败”，内容已经安全写入数据库，可以在正文面板重新同步。
